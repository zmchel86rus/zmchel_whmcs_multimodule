# Импорт / экспорт

Настройки модуля → **Импорт / экспорт**. Один JSON-файл (формат `zmchel_whmcs_multimodule`, версия 1), выбранные разделы или все сразу:

- Страницы и статьи: параметры, все переводы, контент GrapesJS, SEO, настройки sitemap. CSS/JS читаются из generated и включаются как исходный код; при импорте файлы создаются под новым ID страницы.
- Меню: вложенность, переводы названий, размещения и настройки. ID страниц сопоставляются по `slug + auth_type`, меню обновляется по имени. Если на целевом сайте несколько меню с одинаковым именем, импорт требует сначала устранить неоднозначность.
- Настройки: редактируемые константы, строки настроек модуля, подмены, head/footer и robots.txt. Системный режим URL и время последней генерации sitemap остаются локальными.
- Редиректы: правила менеджера и привязки автоматических правил к страницам.
- Rewrite: пользовательские правила. После импорта применяются обычной кнопкой менеджера перезаписи.
- Медиа: только зарегистрированные в медиатеке файлы и размеры, описания и атрибуты. Файлы из остальных вложений WHMCS не собираются. При конфликте с чужим файлом выбирается другое имя, ссылки в импортируемых данных обновляются.

Импорт обновляет совпадения, добавляет новые записи и сохраняет прочие. Выбранные разделы, отсутствующие в файле, пропускаются. Если импортировать только меню/автоматические редиректы на новый сайт, соответствующие страницы нужно предварительно импортировать или выбрать вместе с ними. URL исходного сайта заменяются на SystemURL целевого; внешние URL сохраняются. Для переноса картинок вместе со страницами выберите медиатеку в той же операции.

Лимит JSON — 32 МиБ; также действуют `upload_max_filesize` и `post_max_size`. Экспорт больших разделов может требовать повышения лимитов памяти PHP. Ревизии, собранные Smarty-переменные, учётные записи/секреты WHMCS и файлы тем не входят в экспорт. Импорт использует существующие таблицы; DDL выполняется только штатным менеджером БД/активацией.

Формы используют общий POST-обработчик `main.js`, штатные nonce и доступ к настройкам модуля. Перед импортом выводится подтверждение обновления записей. Данные БД изменяются в транзакции; перезаписанные файлы восстанавливаются при исключении. Константы импортируются только полным выбранным набором: если хотя бы одну записать нельзя, операция завершается ошибкой. На время операции импорта используется файловая блокировка. После успеха страница автоматически обновляется на вкладке импорта, чтобы формы показывали актуальные настройки. Sitemap нужно пересоздать отдельно.

Проверка в PHP-окружении проекта:

```sh
php modules/addons/zmchel_whmcs_multimodule/tests/transfer.php
php modules/addons/domain_auction/tests/sitemap_hook.php
```

Тесты используют временные каталоги и SQLite, без подключения к рабочей БД.

## Sitemap аукциона

`crons/generate_sitemaps.php` перенесён в `includes/hooks/generate_sitemaps.php`. Генератор подключается автоматически WHMCS и выполняется по `DailyCronJob`. Старую отдельную cron-команду для этого файла нужно удалить. Штатный cron WHMCS продолжает работать.

Хук не выводит текст и не завершает процесс через exit. Результат/ошибки записываются в Activity Log. Сохраняются 5000 доменов на файл, `daily`, приоритет `0.7` и чужие записи общего sitemap_index. Модульный генератор страниц/статей сохраняет свой график в `AfterCronJob`.
