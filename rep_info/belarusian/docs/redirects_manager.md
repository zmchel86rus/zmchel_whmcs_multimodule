# Перанакіраванні

Дакладныя адрасы: крыніца → прызначэнне. Крыніца — гэта шлях ад кораня сайта або URL гэтага сайта. Прызначэнне — шлях або поўны URL HTTP(S). Правіла без параметраў запыту таксама адпавядае запытам з імі; адрас прызначэння выкарыстоўваецца ў зададзеным выглядзе. Правілы дзейнічаюць для запытаў GET/HEAD, якія даходзяць да WHMCS.

Прадвызначана: 14 дзён. Адлік вядзецца ад апошняй змены апублікаванай старонкі або яе актыўных перакладаў; калі змен не было — ад стварэння. Укажыце 0, каб не было затрымкі. Аўтаматычныя правілы выкарыстоўваюць HTTP 301.

Адрасы старонак-замен аўтаматычна перанакіроўваюць на сістэмныя старонкі, якія яны замяняюць. Калі замена мае некалькі адрасоў прызначэння, выкарыстоўваецца першы з наладжаных. Гэтыя перанакіраванні працуюць пры ўключаных заменах незалежна ад правілаў менеджара перанакіраванняў.

Увядзіце правільны шлях, які пачынаецца з /, або поўны URL HTTP(S). Крыніца павінна належаць гэтаму сайту; фрагменты # не падтрымліваюцца.

## HTTP

Правілы падтрымліваюць HTTP-коды `301`, `302`, `303`, `307`, `308` і дзейнічаюць толькі на запыты `GET`/`HEAD`, якія даходзяць да WHMCS. Крыніца дакладна супастаўляецца па шляху і, калі зададзены, параметрах запыту; параметры прызначэння замяняюць зыходныя. Менеджэр захоўвае правілы ў `zm_pb_redirects`, але не стварае табліцу падчас запыту: карыстайцеся **Базай даных модуля**. Існыя палі URL абмежаваныя 128 байтамі.

Ручныя правілы маюць перавагу перад аўтаматычнымі. Змена slug апублікаванай старонкі пасля зададзенай затрымкі можа стварыць аўтаматычны `301` для кожнай актыўнай мовы; публікацыя чарнавіка гэтага не робіць. Наступныя перайменаванні абнаўляюць мэты старых правіл. Правіла з параметрамі запыту мае перавагу перад правілам толькі для шляху. Зыходны URL павінен належаць гэтаму сайту і не ўтрымліваць фрагмент `#`.
