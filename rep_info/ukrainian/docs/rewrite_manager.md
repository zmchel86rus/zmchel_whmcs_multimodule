# Правила перезапису

## WHMCS

Правила для мовних URL, зокрема сторінок у /ru/, /en/ та інших префіксах. Мови беруться із supported_langs.php; правила додаються до .htaccess перед правилами WHMCS.

Nginx не читає .htaccess: ці правила в ньому не працюють. Аналогічні правила потрібно налаштувати в nginx.

Виявлено зв'язку nginx → Apache. Правила працюють лише для запитів, переданих Apache; nginx не читає .htaccess.

Після додавання або видалення натисніть «Додати або оновити правила», щоб застосувати зміни до .htaccess.

## Мапа сайту, перенаправлення та rewrite

У **Налаштуваннях модуля** увімкніть генерацію мапи й виберіть частоту. У вкладці **Мапа сайту** перегляньте останній запуск і заплановані URL, натисніть **Згенерувати мапи сайту** та відкрийте `sitemap_index.xml` і вкладені файли. Автоматична генерація залежить від cron WHMCS. Індекс може включати інші файли мап у корені сайту. Перевизначення використовують публічні адреси; неопубліковані мови не повинні з’являтися. Докладніше: [мапи сайту](sitemap_manager.md).

У **Менеджері перенаправлень** вкажіть джерело `/old-page/` і ціль `/new-page/`, виберіть `301` для постійної або `302` для тимчасової зміни, увімкніть правило, збережіть і перевірте стару адресу. Автоматичне правило після зміни slug має окремі налаштування ввімкнення й мінімального віку сторінки. Докладніше: [перенаправлення](redirects_manager.md).

У **Менеджері rewrite-правил** натисніть **Перевірити правила**, потім **Додати або оновити правила** для запису `.htaccess`. Для власного правила вкажіть шаблон URL, ціль і прапорці та застосуйте правила знову. `.htaccess` використовує Apache; для Nginx потрібні відповідні серверні правила. Помилкове правило може вплинути на весь сайт.
