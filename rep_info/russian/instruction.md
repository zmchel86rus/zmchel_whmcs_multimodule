# Инструкция по работе с ZMChel WHMCS Multimodule

**Перед использованием обязательно сгенерируйте соли и поместите их в `module_init.php` (`ZM_PB_ADMIN_SALT`, `ZM_PB_SECURE_SALT`, `ZM_PB_NONCE_SALT`). Модуль разрабатывался и тестировался на WHMCS 8.13.1; Apache поддерживается полностью (100%). На Nginx он тоже может работать, но языковая маршрутизация главной страницы требует отдельной проверки.**

Это руководство для сотрудников, которые наполняют сайт через админку WHMCS. Для повседневной работы с текстами, изображениями и меню программировать не нужно. Если вы меняете адреса, перенаправления, правила сервера или код, сначала сохраните экспорт настроек: эти изменения влияют на уже опубликованные страницы.

## 1. Куда нажимать и что где находится

1. Войдите в **админку WHMCS** с учётной записью, которой разрешён доступ к дополнительному модулю.
2. Откройте **Дополнения → zmchel WHMCS Multimodule**. Если в вашем оформлении админки название другое, откройте страницу дополнения с вкладками «Список страниц», «Менеджер медиафайлов», «Менеджер меню» и т. д.
3. Для ориентира используйте верхние вкладки модуля:

| Раздел | Что в нём делать |
| --- | --- |
| Список страниц | Создать, найти, изменить или убрать страницу; настроить подмену системной страницы. |
| Карта сайта | Проверить файлы sitemap и запустить генерацию вручную. |
| Менеджер медиафайлов | Загрузить изображение, найти файл, изменить его описание или оптимизировать. |
| Менеджер меню | Создать меню, заполнить пункты и выбрать место вывода. |
| Менеджер правил перезаписи | Проверить и применить правила `.htaccess`, добавить свои правила Apache. |
| Менеджер редиректов | Перенаправить старый адрес на новый. |
| База данных модуля | Проверить таблицы и восстановить недостающие. Для администратора сайта. |
| Настройки модуля | Режимы работы, sitemap, подмены, код в шапке/подвале, robots.txt, импорт/экспорт. |

**Термины:** «slug» — часть адреса после домена, например `contact` в `/contact/`; «публикация» — страница доступна посетителям; «черновик» — готовится в админке; «блок» — отдельная часть содержимого; «подмена» — вывод страницы конструктора на адресе существующей страницы WHMCS.

## 2. Как создать и опубликовать страницу

1. Откройте **Список страниц → Добавить страницу**.
2. Впишите **Название страницы**. Это рабочее название в списке; заголовок вкладки браузера заполняется отдельно в SEO.
3. Впишите **Slug страницы** латиницей, цифрами и дефисами. Например, `about-us`. Не вписывайте домен, `/ru/`, знак `?` или `.php`.
4. Выберите **Тип авторизации**:
   - **Смешанный** — страница доступна всем; внутри неё можно вставить блоки только для гостей или вошедших пользователей.
   - **Для авторизованных** — вся страница предназначена вошедшим пользователям.
   - **Для неавторизованных** — вся страница предназначена гостям.
5. Выберите **Статус страницы**. Для подготовки используйте **Черновик**; для показа посетителям — **Опубликовано**. **Отложено** оставляет страницу вне публичной выдачи; отдельного календаря автоматической публикации в этой форме нет. **В корзине** убирает страницу из работы.
6. Выберите **Тип страницы**: обычная **Страница**, **Статья** или **Системная страница**. Системный тип не публикуется как обычная пользовательская страница и не добавляется в sitemap.
7. Отметьте **Поддерживаемые языки страницы**. Язык сайта по умолчанию уже включён.
8. Нажмите **Сохранить**. Затем откройте созданную запись через **Редактировать** в списке.

В списке можно искать по названию и фильтровать по авторизации, типу, статусу и языку. Кнопка **Сбросить** снимает фильтры. **Посетить** открывает публичную страницу; **Удалить** сначала переносит её в корзину. Для окончательного удаления откройте корзину и подтвердите удаление там.

### Вкладки редактора страницы

| Вкладка | Что заполнять |
| --- | --- |
| Главные настройки | Название, slug, авторизация, статус, тип, языки. |
| Настройки контента | Содержимое страницы отдельно для каждого языка. |
| Настройки Meta данных | Заголовок, описание, крошки, Open Graph, Twitter, canonical, robots, Schema.org. |
| Настройки страницы для карты сайта | Частота изменений и приоритет. Доступно для опубликованной несистемной страницы. |

У каждой части есть собственная кнопка **Сохранить**; внизу есть **Сохранить всё**. После сохранения проверьте сообщение об успехе. Если браузер предупреждает о несохранённых изменениях, вернитесь к указанной языковой вкладке и сохраните её.

## 3. Как работать с редактором блоков

1. Откройте страницу и перейдите в **Настройки контента**.
2. Выберите вкладку нужного языка.
3. Возьмите блок из списка GrapesJS и перетащите его на полотно. Вложенный блок перетащите внутрь секции, колонки или другого контейнера.
4. Щёлкните по блоку на полотне. В верхней части полотна появятся **GrapesJS · Настройки блока**. Там меняются параметры именно выбранного блока. Шеврон слева сворачивает панель; состояние запоминается в браузере.
5. Текст редактируйте внутри текстового блока. Для расширенного оформления выберите блок с TinyMCE; для Smarty и кода используется редактор кода внутри блока.
6. Нажмите **Сохранить** для текущего языка и откройте **Перейти** для проверки результата на сайте.

Слева/в панели блоков доступны: обычный и расширенный текст, заголовок, изображение, видео, карта, ссылка, кнопка, цитата, список, таблица, вопрос–ответ, аккордион, содержание, пагинация, фильтры, контактная форма, прогресс, разделитель, отступ; секция, Flex, Grid, обычный `div`, изображение с текстом, первый экран, карточка, галерея, карусель; зоны для вошедших и гостей; при разрешении в настройках — Smarty; блоки CSS и JavaScript. Название и доступность некоторых блоков зависят от перевода интерфейса и настроек модуля.

**Практический пример — два столбца с текстом и изображением:** перетащите «Секция», выберите её, в «Настройках блока» задайте режим колонок и число `2`; затем перетащите «Изображение» в первую колонку, «Текст» во вторую. Там же настройте число колонок для планшета и телефона. Flex и Grid нужны, когда требуются собственное направление, перенос, ширина ячеек или объединение ячеек.

**Таблица:** выберите блок таблицы, задайте строки и столбцы, включите заголовок/подвал при необходимости. **Карусель:** добавьте слайды, настройте автопрокрутку, зацикливание, скорость и количество видимых слайдов для разных экранов. **Вопрос–ответ** подходит для FAQ и его разметки; отдельный **Аккордион** — для обычного раскрываемого содержимого. В редакторе раскрытие пункта делается двойным кликом, чтобы одиночный клик не мешал выделять и менять текст.

**Заголовок:** в его настройках выберите уровень `H1`–`H6`, размер и жирность. На странице обычно оставляют один основной `H1`. **Содержание** собирает следующие за ним заголовки и формирует переходы к ним. **Отступ** задаётся в пикселях. **Изображение:** заполните понятный `alt`; размер и адаптивные варианты формируются из данных медиатеки, если включена соответствующая настройка блока.

Если трудно выбрать родительский контейнер, воспользуйтесь деревом компонентов GrapesJS. Панель настроек работает и в полноэкранном режиме редактора. Для удаления выбирайте именно нужный элемент в дереве или на полотне: удаление ячейки и удаление всей секции — разные действия.

### Перенос содержимого между языками

Над редактором языка расположены **Скопировать с контентом в**, **Скопировать структуру в**, **Клонировать в** и список языков назначения.

- **Скопировать с контентом** добавляет копию блоков в редактор целевого языка вместе с текстом.
- **Скопировать структуру** добавляет раскладку блоков для последующего перевода текста.
- **Клонировать** заменяет целевой редактор копией исходного; если там уже есть содержимое, появится подтверждение.

Сначала выберите язык в списке, затем нажмите нужную кнопку. После переноса откройте целевую языковую вкладку, переведите тексты и нажмите **Сохранить**. В «Настройках блока» также есть перенос одного выбранного блока в другой язык.

## 4. Языки и ссылки

Модуль использует список языков из `supported_langs.php`. При включённой языковой маршрутизации и красивых URL язык по умолчанию идёт **без префикса**: `/contact/`; остальные получают префикс, например `/ru/contact/`, `/de/contact/`. Переключение языка страницы само по себе не должно менять язык профиля клиента.

### Ссылка в содержимом страницы

1. Добавьте блок **Ссылка** или выберите существующую ссылку на полотне.
2. В **GrapesJS · Настройки блока** заполните **Адрес ссылки**, например `/contact/`.
3. Включите **Учитывать язык текущей страницы в адресе**, если это ссылка на языковую страницу сайта.
4. Выберите, открывать ли её в той же или новой вкладке. При необходимости добавьте `nofollow` и понятное доступное имя для ссылки без текста.
5. Сохраните контент и проверьте ссылку в двух языковых версиях.

То же поле доступно у блока **Кнопка**, когда её действие — **Открыть ссылку**, и у ссылки внутри блока первого экрана. Для новых блоков переключатель включён. У уже сохранённых блоков без этой настройки адрес остаётся как был, пока вы явно не включите её. При включённой настройке `/contact/` на русской версии станет `/ru/contact/`, а на языке по умолчанию останется `/contact/`. Если в адресе уже есть другой языковой префикс, он заменяется. Параметры `?…` и якорь `#…` сохраняются.

Выключайте переключатель для **внешнего адреса**, файла, `mailto:`, `tel:`, якоря `#section` или маршрута WHMCS без языковой версии, например `/login` и `/clientarea.php`. Обработчик оставляет такие адреса неизменными и при включённой опции, но явное выключение показывает намерение редактора. **Важно:** галочка меняет адрес, а не создаёт перевод целевой страницы. Перед публикацией убедитесь, что целевой язык страницы включён и опубликован. Ссылки, набранные внутри текста TinyMCE/Smarty, не имеют отдельного переключателя блока — проверяйте их вручную.

## 5. Как заполнить SEO и карту сайта для страницы

1. Откройте страницу → **Настройки Meta данных** → выберите язык.
2. Заполните обязательные **Заголовок страницы (Title)** и **Мета описание страницы**. Пишите их на языке выбранной вкладки.
3. При необходимости заполните подпись для **хлебных крошек** и включите/выключите их показ.
4. При необходимости выберите изображение и включите блоки **Open Graph** и **Twitter**. Если их отдельные поля оставить пустыми, редактор использует основные метаданные там, где предусмотрен запасной вариант.
5. Проверьте **Канонический URL**, **Robots** и **Тип Schema**. Для обычной страницы подходит `WebPage`, для статьи — соответствующий тип статьи, для контактов — `ContactPage`. Не выбирайте `Organization` как основной тип просто потому, что у сайта есть организация.
6. Нажмите **Сохранить**. Повторите для других языков.
7. Во вкладке **Настройки страницы для карты сайта** выберите частоту и приоритет; сохраните. Она доступна только для опубликованной несистемной страницы.

При публикации проверьте исходный код страницы или SEO-инструмент: должен быть корректный `title`, `description`, нужные языковые ссылки и ровно один осмысленный `H1`. Для страниц с подменой в карте сайта используется публичный адрес заменяемой страницы, а внутренний адрес страницы-подмены туда не добавляется.

## 6. Как заменить существующую страницу WHMCS

Подмена связывает **системный адрес** с **созданной страницей конструктора**. Например, содержимое страницы с рабочим slug `mainpage` может показываться по адресу главной `/`.

1. Сначала создайте страницу-подмену, заполните её содержимое и метаданные, сохраните и опубликуйте.
2. Вернитесь в **Список страниц**, прокрутите до **Переопределение страниц**.
3. Нажмите **Добавить переопределение**.
4. В первом списке выберите страницу WHMCS, адрес которой надо заменить; во втором — страницу конструктора.
5. Выберите тип и нажмите **Сохранить**.

| Тип | Что увидит посетитель |
| --- | --- |
| Полное | Контент и метаданные страницы конструктора вместо штатной страницы. |
| Добавление (до) | Блоки конструктора перед штатным содержимым. |
| Добавление (после) | Блоки конструктора после штатного содержимого. |
| Только мета/SEO данные | Штатное содержимое и метаданные из конструктора. |
| Добавление (до/после) + мета | Соответствующее добавление блоков и замена метаданных. |

Одна и та же системная страница не выбирается дважды в разных строках. После сохранения откройте **публичный адрес WHMCS**, а не рабочий slug страницы-подмены. Модуль перенаправляет с рабочего адреса подмены на её публичный адрес, если они различаются. Проверяйте результат как гость и как вошедший клиент: режимы авторизации влияют на показ. Если нужно ограничить отдельные участки, оставьте странице тип **Смешанный** и используйте зоны контента для гостей/авторизованных.

## 7. Изображения и медиатека

1. Откройте **Менеджер медиафайлов** и нажмите **Загрузить медиафайл**.
2. Выберите файл. Для изображения заполните **Alt** — краткое описание того, что на нём изображено. **Название**, **Заголовок** и **Описание** помогают искать и подписывать файл.
3. Нажмите кнопку загрузки в появившейся форме.
4. Найдите файл через строку поиска и фильтр типа. Если файлов много, нажимайте **Загрузить ещё**.
5. Для вставки на страницу выберите блок **Изображение**, нажмите **Выбрать изображение** в настройках блока и выберите файл из медиатеки. Сохраните страницу.

Менеджер создаёт несколько размеров изображений. В карточке медиафайла есть **Оптимизировать изображение** для уже загруженного файла; отметка о прошлой оптимизации остаётся видимой, но не блокирует повторную попытку. Проверяйте качество после оптимизации, особенно текст на баннерах. В блоке изображения можно выключить адаптивный набор вариантов (`srcset`), если конкретной картинке он не подходит. Не вставляйте служебный `data:image/svg+xml…` как адрес настоящей картинки.

## 8. Меню сайта

1. Откройте **Менеджер меню** и выберите **Создать меню**.
2. Впишите **Название меню**.
3. В левой части отметьте нужные **Страницы** или **Статьи**, нажмите **Добавить в меню**. Для внешнего адреса, системной страницы или заголовка колонки используйте **Произвольная ссылка**: заполните надпись и URL, затем нажмите **Добавить**.
4. В разделе **Структура меню** перетаскивайте пункты для порядка и вложенности. Откройте настройки конкретного пункта для текста, подписей на других языках, новой вкладки, видимости, CSS-классов и других атрибутов.
5. Для **Произвольной ссылки** выберите, подставлять ли язык текущей страницы в URL. Для `/clientarea.php` или адреса, который не имеет языкового маршрута, используйте вариант **Использовать указанный URL без изменений**.
6. В **Настройках меню** включите меню, выберите **Дополнить** или **Заменить** штатные пункты WHMCS, а также **PC и mobile**, **Только PC** или **Только mobile**.
7. В **Размещении** отметьте нужную область: основной/дополнительный navbar, основной/дополнительный sidebar или **Меню в подвале**. На одном месте может быть назначено только одно меню.
8. Нажмите **Сохранить меню** и проверьте сайт на компьютере и телефоне.

Для подвала пункты верхнего уровня становятся колонками, вложенные — ссылками; заголовку колонки без перехода можно задать URL `#`. Вывод каждой области также должен быть разрешён в **Настройках модуля**. Если менеджер показывает, что таблицы меню отсутствуют, откройте **База данных модуля** и восстановите недостающие таблицы. Подробнее: [docs/menus.md](../../docs/menus.md).

## 9. Контактная форма

1. На вкладке контента перетащите **Контактная форма** и выберите её.
2. В **Настройках блока** задайте заголовок, описание, тему и текст кнопки.
3. Выберите **Действие**: **Тикет в WHMCS** или **Отправка email**. Для тикета выберите отдел поддержки; для email укажите **Email получателя** в самом блоке.
4. Добавьте поля. Для каждого задайте название, тип, обязательность и проверку значения. У гостевого тикета должны быть поля с ролями имени и email отправителя.
5. Для выпадающего списка вписывайте по одной строке в формате `значение : Надпись`, например `sales : Отдел продаж`. В письме/тикете попадёт значение `sales`, посетитель увидит «Отдел продаж».
6. Для нескольких согласий добавляйте несколько полей типа **Согласие**. У каждого свой текст и признак обязательности. Ссылки в тексте можно указать безопасным HTML, например `<a href="/privacy/">политикой</a>`.
7. Расставьте поля: ширина, новая строка, порядок; при необходимости выберите Flex/Grid раскладку. Включите **Капча**, если она нужна. Форма использует тип и ключи капчи, настроенные в WHMCS.
8. Для email выберите **Служебное — без шаблона WHMCS** или обычное оформление. Служебный вариант удобен для внутренних уведомлений.
9. Сохраните страницу и отправьте тестовое сообщение как обычный посетитель. Проверьте получателя/тикет, текст ошибок и сброс формы после успешной отправки.

Доставка email зависит от почтовых настроек WHMCS и сервера: если системная функция `mail()` не работает, настройте действующий SMTP в WHMCS. Не считайте зелёный статус редактора подтверждением доставки письма — подтвердите это тестовым получением.

## 10. Списки, фильтры и пагинация

Блок **Пагинация** связывается с конкретным блоком списка, например со Smarty-блоком. В его настройках можно выбрать целевой блок, число записей по умолчанию, число видимых кнопок, режим адресов `/page/N/` или `?page=N`, выбор количества 10/25/50/100/250 и запрет индексации страниц 2 и далее. Перемещаемый мини-блок выбора количества можно поставить рядом с кнопками или в другом месте макета. Изменение `count` в адресной строке ограничено на сервере диапазоном 10–250.

**Как сделать:** сначала добавьте блок, который выводит записи; затем **Пагинация**; в настройках пагинации укажите именно этот блок и источник данных. Сохраните и откройте страницу 2, проверьте, что список реально меняется и ссылки не накапливают повторяющиеся параметры. Для поиска и дат используйте блок **Фильтры** — отдельного блока «Поиск» в палитре нет. Фильтры могут использовать поля текста, диапазона и даты; результат должен быть связан с тем же списком. Подробнее: [docs/pagination.md](../../docs/pagination.md).

## 11. Smarty, CSS и JavaScript

Блок **Smarty** нужен, когда на странице должны выводиться уже подготовленные WHMCS/другим модулем переменные. Он появляется при включённой настройке **Использование Smarty переменных**. Выберите блок, откройте редактор кода, найдите нужную переменную среди собранных подсказок и сохраните. Доступность переменной зависит от страницы и момента, когда другой модуль её создаёт. В редакторе разрешён только предусмотренный шаблонный синтаксис; PHP, SQL и прямой доступ к БД через Smarty-блок запрещены.

Пример простого вывода: `{$pageTitle|escape}`. Для массива/коллекции используйте разрешённые конструкции Smarty, проверьте страницу как гость и клиент. Никогда не выводите целиком объект или массив с персональными данными. Подробное описание ограничений и сбора переменных: [docs/smarty.md](../../docs/smarty.md).

Блоки **Custom CSS** и **Custom JS** редактируются внутри полотна; они относятся к конкретной странице. Перед публикацией проверьте их на телефоне и на других языковых версиях. Глобальный код страницы/сайта также доступен в **Настройках модуля → Шапка сайта / Подвал сайта**. Доступ к этим настройкам следует давать только тому, кто понимает HTML, CSS и JavaScript.

## 12. Менеджеры sitemap, редиректов и rewrite

### Карта сайта

1. В **Настройках модуля → Настройки работы карты сайта** включите генерацию и выберите частоту.
2. В **Карта сайта** проверьте время последней генерации и список будущих адресов.
3. Нажмите **Сгенерировать карты сайта** для немедленного обновления. Откройте ссылку на `sitemap_index.xml`, затем ссылки на файлы страниц/статей.

Автоматическая генерация запускается после cron WHMCS, когда наступит заданный срок. В индекс включаются и другие sitemap-файлы, лежащие в корне сайта. Адреса страницы-подмены записываются под публичным адресом заменяемой страницы. Отдельная страница с неопубликованным языком не должна внезапно появиться в карте. Подробнее: [docs/sitemaps.md](../../docs/sitemaps.md).

### Перенаправления

1. Откройте **Менеджер редиректов**.
2. Введите **Откуда** (`/old-page/`) и **Куда** (`/new-page/`).
3. Выберите статус: обычно `301` для постоянного переезда, `302` для временного.
4. Оставьте **Активен**, нажмите **Сохранить**.
5. Откройте старый адрес в отдельной вкладке и убедитесь, что открывается нужная страница.

Автоматическое создание редиректа при изменении slug настраивается отдельно в **Настройках модуля → Настройки редиректов**: его можно включить и задать минимальный срок после публикации/последнего изменения. Подробнее: [docs/redirects.md](../../docs/redirects.md).

### Rewrite для языковых адресов

В **Менеджере правил перезаписи** нажмите **Проверить правила**. Кнопка **Добавить или обновить правила** записывает их в `.htaccess`. Своё правило добавляется в полях **Шаблон URL → Куда направить → Флаги**, после чего снова нажмите **Добавить или обновить правила**, иначе новое правило ещё не действует. **Важно:** `.htaccess` исполняет Apache; nginx требует соответствующую настройку сервера. Страница менеджера предупреждает о распознанном веб-сервере. Меняйте правила только если знаете, куда они направляют запрос: ошибочное правило может затронуть весь сайт.

## 13. Настройки, импорт и обслуживание

В **Настройках модуля** находятся:

- **Переменные модуля**: красивые ссылки, языковая маршрутизация, подмены, области меню, режим обслуживания, доступность Smarty и прочее. Отключение функции скрывает или меняет соответствующее поведение на сайте.
- **Настройки редиректов**: включение и правила автоматического перенаправления при смене slug.
- **Настройки работы карты сайта**: включение и частота обновления.
- **Шапка сайта / Подвал сайта**: произвольный код для вывода в общей оболочке сайта.
- **Robots.txt**: правила для поисковых роботов. После изменения проверьте публичный `/robots.txt`.
- **Импорт / экспорт**: перенос данных модуля между установками или создание резервной копии.

### Экспорт перед крупными правками

1. Откройте **Настройки модуля → Импорт / экспорт**.
2. В колонке экспорта оставьте **Все** либо выберите только нужные разделы.
3. Нажмите **Экспорт** и сохраните JSON-файл в надёжном месте.
4. Перед импортом в другом окружении проверьте системный адрес сайта и доступность нужных медиафайлов.

### Импорт

1. На той же вкладке выберите разделы для импорта.
2. Выберите ранее выгруженный JSON-файл.
3. Нажмите **Импорт** и подтвердите операцию. Импорт может обновить существующие записи в выбранных разделах.
4. Проверьте страницы, меню и медиа. При импорте rewrite-правил отдельно примените их через менеджер; карту сайта отдельно перегенерируйте.

Экспорт не является полным резервным копированием WHMCS: в него не входят учётные записи, секреты, ревизии страниц и файлы тем. Подробные состав и ограничения: [docs/transfer.md](../../docs/transfer.md).

**База данных модуля** показывает требуемые таблицы и их состояние. Если раздел модуля пишет о недостающей колонке или таблице, зайдите сюда и выполните предлагаемое восстановление. В обычной работе с контентом эту вкладку не трогают. Режим обслуживания модуля закрывает публичные страницы обычным посетителям и оставляет работу администратора; проверяйте его после включения в отдельном окне браузера без входа.

### Настройка модуля при первом запуске — для администратора

1. Включите дополнение в WHMCS и выдайте ответственным сотрудникам право доступа к нему.
2. Откройте **База данных модуля** и убедитесь, что необходимые таблицы и колонки существуют. Если интерфейс предлагает исправление схемы, примените его до создания меню и форм.
3. В **Настройках модуля → Переменные модуля** проверьте режим красивых ссылок, языковую маршрутизацию и разрешение подмен. Если меню должны выводиться в navbar/sidebar/footer, включите соответствующие переключатели.
4. Если сайт обслуживает Apache, откройте **Менеджер правил перезаписи**, проверьте и примените правила. Если перед PHP стоит nginx, настройку его маршрутов выполняет администратор сервера: `.htaccess` ему не подходит.
5. Убедитесь, что штатный cron WHMCS действительно запускается: без него не произойдёт автоматическое обновление sitemap.
6. Проверьте право PHP на запись в корень сайта для sitemap, в каталог медиафайлов для загрузки и в служебные каталоги модуля для сохранения данных. При ошибке интерфейс обычно показывает, какой раздел не удалось записать.
7. Создайте тестовую страницу и откройте её в языке по умолчанию и ещё одном языке; затем проверьте меню, подмену и редиректы отдельно.

Не отключайте языковые маршруты только из-за того, что одна ссылка ведёт неправильно: сначала проверьте настройку этой ссылки, наличие перевода целевой страницы и правила веб-сервера. Переключатели для Smarty и сбора переменных включайте только для сотрудников, которым действительно нужен этот блок.

## 14. Проверка результата и частые проблемы

### Перед тем как отправить страницу заказчику

1. Проверьте, что статус **Опубликовано**, нужный язык включён, а контент и метаданные **сохранены** в каждой языковой вкладке.
2. Откройте публичную ссылку как обычный посетитель. Затем проверьте на телефоне или в узком окне.
3. Проверьте заголовок, изображения, `alt`, кнопки, ссылки и контактную форму. Для языковых ссылок откройте две версии страницы и убедитесь, что адрес назначения меняется корректно.
4. Для подмены откройте именно системный адрес, например `/contact/`, и проверьте, что рабочий slug страницы-подмены не остаётся отдельной публичной страницей.
5. При наличии меню откройте его на компьютере и телефоне. При изменении slug проверьте старый URL и редирект.
6. После изменений публикации или подмен запустите sitemap вручную и откройте `sitemap_index.xml`.

### Если что-то не работает

| Ситуация | Что проверить сначала |
| --- | --- |
| Страница отдаёт 404 | Статус «Опубликовано», slug, наличие языковой версии, красивые URL и rewrite-правила. Для системного маршрута проверьте, существует ли его подмена. |
| На другом языке пусто | Включён ли язык у страницы, сохранены ли его контент и SEO. Копирование структуры само по себе не переводит текст. |
| Ссылка ведёт на `/ru/login` или похожий адрес | В блоке ссылки/кнопки выключите учёт языка, сохраните; для внутренних WHMCS-адресов используйте их штатный путь. |
| Меню не видно | Меню активно, назначено нужное размещение, включена соответствующая область в настройках модуля, выбран верный режим PC/mobile. |
| Картинка не показывается | В блоке выбран реальный файл из медиатеки, страница сохранена, URL файла открывается отдельно. |
| Письмо формы не приходит | Верен email получателя, отправлена тестовая форма, почта/SMTP WHMCS настроены, проверьте журнал ошибок. |
| Не получается добавить/сохранить меню | Проверьте обязательное название, URL у произвольного пункта и состояние таблиц в «База данных модуля». |
| Sitemap не обновляется | Включена генерация, работает cron WHMCS, у PHP есть доступ к записи в корень сайта. Попробуйте ручную кнопку и прочитайте сообщение ошибки. |
| Новое rewrite-правило не действует | После сохранения нажмите «Добавить или обновить правила»; на nginx настройте эквивалентное правило в конфигурации сервера. |

Если сообщаете о проблеме разработчику, приложите: публичный URL, номер/название страницы в админке, язык, какое действие сделали, что ожидали и что увидели, а также точный текст сообщения об ошибке. Секреты и пароли в обращение не вставляйте.
