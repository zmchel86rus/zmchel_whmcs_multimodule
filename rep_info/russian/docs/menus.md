# Менеджер меню

Раздел `menu_manager` в админке модуля:

- несколько независимых меню;
- списки страниц и статей, поиск, добавление выбранных страниц;
- произвольные ссылки и пункты-заголовки с URL `#`;
- перетаскивание, выбор родителя, кнопки изменения порядка и вложенности;
- подпись, переводы подписи, новая вкладка, title, описание, CSS-классы,
  rel, иконка, видимость для гостей / авторизованных;
- автоматическое добавление новых опубликованных страниц;
- дополнение или замена штатных пунктов WHMCS;
- PC, mobile или смешанный режим.

Удаление родителя в редакторе переносит его дочерние пункты на уровень
удалённого родителя. Дерево ограничено 10 вложенными уровнями и 300 пунктами.
Сохранение меню и структуры выполняется одной транзакцией.

## Размещения и переключатели

| Размещение WHMCS | Константа |
| --- | --- |
| ClientAreaPrimaryNavbar | ZM_PB_ENABLE_MAINNAV |
| ClientAreaSecondaryNavbar | ZM_PB_ENABLE_SECONDARYNAV |
| ClientAreaPrimarySidebar | ZM_PB_ENABLE_MAINSIDEBAR |
| ClientAreaSecondarySidebar | ZM_PB_ENABLE_SECONDARYSIDEBAR |

Переключатели доступны в настройках модуля. При отключении обработчик
соответствующей панели не загружается и не обращается к БД.
Без активного назначения штатное меню WHMCS не изменяется.
На каждом размещении назначается одно меню; одно меню можно назначить
на несколько размещений. Назначение занятого места переносит его к новому меню.

PC — ширина от 768px, mobile — до 767px. В режиме замены только для одного
размера штатное меню сохраняется для другого размера. Стандартные шаблоны
WHMCS выводят один уровень подменю; ассеты модуля добавляют более глубокие
уровни navbar. В sidebar используется вложенный список с раскрытием.
Ссылки верхних пунктов с подменю остаются кликабельными; для раскрытия
предусмотрена отдельная кнопка.

## Языки и доступ

На системных маршрутах WHMCS вне `ZM_PB_MAINSYSTEM_DEFAULT_PAGES` (например,
`clientarea.php`, `password/reset`, `account/security`) язык переводов и меню
берётся из сохранённого выбора пользователя. Отсутствие префикса на таком URL
не переключает меню на язык сайта по умолчанию. Профиль и сессия при просмотре
страницы не изменяются. На страницах модуля и доступных для переопределения
страницах продолжает действовать язык URL.

У «Произвольной ссылки» настройка «Язык адреса ссылки» позволяет выбрать
«Использовать указанный URL без изменений», например `/clientarea.php`.
Переводы подписи пункта продолжают работать. По умолчанию адрес локализуется,
как и раньше. Настройка сохраняется в `zm_pb_menu_items.localize_url` и переносится
при импорте/экспорте меню. На существующей установке добавьте это поле через
«База данных модуля»; менеджер меню сам схему БД не меняет.

Для страниц в БД меню сохраняется ссылка для языка по умолчанию.
При выводе URL рассчитывается заново с учётом актуального slug, настроек
красивых URL, языковой маршрутизации и доступного опубликованного перевода.
Язык по умолчанию не получает префикса. Для обычных URL используются
`index.php?m=zmchel_whmcs_multimodule&slug=...&lang=...`, без смены языка профиля.
Отсутствующий перевод использует опубликованный перевод по умолчанию.

Пустая подпись пункта-страницы берётся из breadcrumb / meta_title
соответствующего перевода, затем из названия страницы. Введённая подпись
переопределяет её; при наличии перевода подписи используется он.
Внешние URL, mailto, tel, якоря и системные ассеты не получают языковых префиксов.

Черновики, удалённые страницы и недоступные по авторизации страницы
не выводятся. Скрытие родителя скрывает всю его ветку. Произвольные ссылки
с опасными схемами и HTML в подписях отклоняются на сервере.

## Таблицы

- `zm_pb_menus` — настройки меню, включая устройства;
- `zm_pb_menu_items` — пункты и дерево;
- `zm_pb_menu_locations` — назначения размещений.

Общее описание в `inc/menu_schema.php` используется при активации модуля
и в `inc/module/db.php`: доступны создание, восстановление колонок и удаление.
Если таблиц пока нет, менеджер показывает ссылку на раздел «База данных модуля».
Менеджер меню работает только с записями; создание, исправление и удаление таблиц
в административных разделах выполняется только в `module_db`.
При деактивации таблицы удаляются только при включённом `db_action`.

Обработчик вывода — `lib/menu.php`, вспомогательные функции — `inc/menu_manager.php`,
регистрация хуков — `hooks/menu.php`. Ассеты остаются внутри модуля.

Проверка: `php modules/addons/zmchel_whmcs_multimodule/tests/menu.php` и тот же
скрипт с `--plain`. Используется изолированная SQLite в памяти, нужны
PDO SQLite и остальные зависимости WHMCS.
