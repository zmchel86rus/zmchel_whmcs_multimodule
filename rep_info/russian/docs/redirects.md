# Редиректы и языки карты сайта

**Менеджер редиректов** хранит точные правила «исходный адрес → адрес назначения» со статусом HTTP 301, 302, 303, 307 или 308. Правила можно изменять, отключать и удалять; в админке выводится по 50 правил на страницу.

Исходным адресом может быть локальный путь от `/` или абсолютный URL того же сайта. Назначением — путь или HTTP(S)-адрес. Конечные слеши считаются одинаковыми при сравнении, но в назначении сохраняется указанный слеш. Правило с параметрами запроса имеет приоритет над правилом для всего пути. Правило пути работает и для запросов с параметрами; параметры назначения заменяют исходные.

Правила применяются к GET/HEAD-запросам, дошедшим до WHMCS, до конструктора страниц. Они не изменяют `.htaccess`, языковую сессию или профиль. Серверные редиректы и существующие языковые и canonical-редиректы модуля работают отдельно. `ZM_PB_ENABLE_REDIRECTS_MANAGER` включает сохранённые правила. Параметры `ZM_PB_AUTO_REDIRECTS` и `ZM_PB_AUTO_REDIRECT_DAYS` отвечают за автоматические правила; по умолчанию задержка составляет 14 дней, значение 0 убирает её.

При смене slug опубликованной страницы, которая остаётся опубликованной, создаётся автоматический 301. Возраст определяется **до сохранения** по самой поздней дате страницы или активного перевода. Публикация черновика не создаёт редирект. Для каждого доступного языка добавляется своё правило. Последующие переименования обновляют назначения старых автоматических правил; возвращение к прежнему slug удаляет редирект на себя. Ручные правила имеют приоритет.

Если включены подмены страниц, адрес самой страницы-макета ведёт к исходной системной странице независимо от переключателя сохранённых правил. Если один макет подменяет несколько страниц, его адрес ведёт к первой настроенной странице, а карта сайта перечисляет каждую системную страницу отдельно. Переименование макета обновляет `page_overrides.to` в одной транзакции со страницей и автоматическими правилами.

Правила хранятся в `zm_pb_redirects`. Обработчик запроса не создаёт и не исправляет таблицу: для этого есть **База данных модуля**. Столбцы существующей схемы вмещают 128 байт на URL; более длинный ввод отклоняется.

В `sitemap_pages.xml` и `sitemap_posts.xml` указывается пространство имён XHTML. Каждый URL содержит взаимные языковые альтернативы и `x-default` для адреса без префикса на языке по умолчанию. Указываются только активные переводы; резервный перевод обозначается его фактическим языком. Исходные адреса редиректов исключаются из `loc` и альтернатив. Страницы, использующие один макет подмены, остаются отдельными языковыми группами. Обновите XML через **Карту сайта** или дождитесь cron.

Для изолированной проверки с зависимостями проекта запустите `tests/redirects.php` с вариантами `--plain`, `--routes-off`, `--disabled`, `--auto-off`, а также `tests/sitemap.php` с `--plain`, `--routes-off`, `--overrides-off`, `--disabled`. Тесты используют SQLite в памяти; тест карты сайта создаёт временный корень сайта.
