# გადამისამართებები და sitemap ენები

## HTTP

Redirect Manager ქმნის ზუსტ საწყისი → დანიშნულების წესებს HTTP 301, 302, 303, 307 ან 308 კოდით. შეიძლება მათი რედაქტირება, გამორთვა და წაშლა; სიაში თითო გვერდზე 50 წესია. საწყისი მისამართი არის /-ით დაწყებული გზა ან იმავე საიტის სრული URL. დანიშნულება შეიძლება იყოს გზა ან HTTP(S) URL.

ბოლო დახრილი ხაზი დამთხვევისას ტოლფასია, მაგრამ დანიშნულება საკუთარ ფორმას ინარჩუნებს. კონკრეტული query-ის წესი უბრალო გზის წესს უსწრებს; გზის წესი პარამეტრებიან მოთხოვნასაც ემთხვევა. დანიშნულების პარამეტრები საწყისის პარამეტრებს ცვლის. წესები მუშაობს WHMCS-მდე მისულ GET და HEAD მოთხოვნებზე page builder-ის დაწყებამდე. ისინი არ ცვლიან .htaccess-ს, ენის session-ს ან მომხმარებლის პროფილს. ZM_PB_ENABLE_REDIRECTS_MANAGER შენახულ წესებს რთავს.

ავტომატური 301 იქმნება, როდესაც გამოქვეყნებული გვერდის slug შეიცვლება და გვერდი გამოქვეყნებული დარჩება. მონახაზის პირველი გამოქვეყნება გადამისამართებას არ ქმნის. ZM_PB_AUTO_REDIRECT_DAYS-ის ნაგულისხმევი მნიშვნელობა 14 დღეა, 0 კი ლოდინს ხსნის. შემდეგი გადარქმევა ისტორიულ დანიშნულებებს განაახლებს; ძველ slug-ზე დაბრუნება საკუთარ თავზე გადამისამართებას წაშლის. ხელით შექმნილი წესი უპირატესია. WHMCS-ის გვერდის ჩანაცვლების alias თავდაპირველ სისტემურ URL-ზე შეიძლება მივიდეს.

წესები zm_pb_redirects-ში ინახება. მოთხოვნა აკლებული ცხრილის შექმნას არ ცდილობს; გამოიყენეთ Module database. არსებული URL სვეტები 128 bytes-ითაა შეზღუდული. sitemap_pages.xml და sitemap_posts.xml ალტერნატიულ ენებსა და x-default-ს შეიცავს, მაგრამ გადამისამართების საწყის URL-ებს გამორიცხავს. URL-ის ცვლილების შემდეგ XML ხელახლა შექმენით.
