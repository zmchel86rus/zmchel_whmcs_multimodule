# სტრუქტურირებული მონაცემები გამოსატან გვერდში

## Schema.org

Page Editor-ის მეტამონაცემებში აირჩიეთ Schema ტიპი, შეინახეთ და შეამოწმეთ გამოქვეყნებული გვერდი. მენიუ რეალური წარწერებით, ენებითა და მისაწვდომი URL-ებით SiteNavigationElement-ს წარმოქმნის. სარჩევი ფაქტობრივ სათაურებში არსებული anchor-ებით SiteNavigationElement-სა და WebPageElement-ს ქმნის. FAQPage-ში მხოლოდ ხილული და არაცარიელი კითხვები და პასუხები ხვდება. BreadcrumbList იქმნება, როცა client theme-ში სულ მცირე ორი breadcrumb ჩანს.

ორგანიზაციისა და კონტაქტის მონაცემები WHMCS-დან მოდის. გვერდის ენა WebPage-ს ან ContactPage-ს ეკუთვნის; კონტაქტის ხელმისაწვდომი ენები BCP 47 ფორმით ContactPoint.availableLanguage-შია. Organization-ზე გამოგონილი inLanguage არ დაამატოთ. ფილტრები, ველები, გვერდის ზომის არჩევა და საკონტაქტო ფორმა ავტომატურად პროდუქტებად ან სერვისებად არ იქცევა. Flex/Grid, ღილაკები და ჩვეულებრივი accordion მხოლოდ განლაგებაა და შიგთავსის ტიპს არ განსაზღვრავს.

JSON-LD უნდა აღწერდეს იმას, რასაც სტუმარი რეალურად ხედავს. ვარგისი მონაცემიც ვერ იძლევა განსაკუთრებული საძიებო შედეგის გარანტიას. ავტორის მიერ Smarty-სა ან HTML-ში დამატებული მონიშვნა შენარჩუნდება. შეადარეთ საბოლოო JSON-LD საჯარო გვერდის ბმულებს, სათაურებს, კითხვებსა და პასუხებს. დამალული ნაწილი საჯარო FAQ-ში არ უნდა მოხვდეს.

## JSON-LD შემოწმება

ერთი და იგივე URL გახსენით სტუმრისა და შესული კლიენტის სახით. გადაამოწმეთ მენიუსა და breadcrumb-ის ნაჩვენები ტექსტი მონიშვნასთან. Schema.org ჩანაწერი არ ცვლის გამოყენებად ნავიგაციას და საძიებო გაფორმებას არ ჰპირდება.

## ContactPoint.availableLanguage

საკონტაქტო ენები WHMCS-დან მოდის და BCP 47 ტეგებს იყენებს. კონკრეტული გვერდის ენა WebPage-ს ან ContactPage-ს მიეკუთვნება. Organization-ში შეთხზული inLanguage მნიშვნელობა არ ჩაწეროთ.
