# იმპორტი და ექსპორტი

## ZIP არქივი

Module settings → Import / export-ში აირჩიეთ ყველა ან საჭირო განყოფილება. ექსპორტი ქმნის ZIP არქივს manifest.json-ით და გვერდების ცალკე CSS/JS ფაილებით. JSON ფაილების იმპორტიც მხარდაჭერილია. საიტის გადატანამდე ან მნიშვნელოვანი პარამეტრების შეცვლამდე ორიგინალი არქივი შეინახეთ.

- **გვერდები და სტატიები:** პარამეტრები, თარგმანები, GrapesJS შიგთავსი, SEO და sitemap. CSS/JS იმპორტისას ახალი გვერდის ID-ებისთვის თავიდან იქმნება.
- **მენიუები:** იერარქია, თარგმნილი წარწერები, ადგილები და პარამეტრები. გვერდები slug-ისა და auth_type-ის წყვილით, მენიუები სახელით ემთხვევა.
- **პარამეტრები:** რედაქტირებადი კონსტანტები, გვერდების ჩანაცვლება, header/footer და robots.txt. URL რეჟიმი და ბოლო sitemap დრო ადგილზე რჩება.
- **გადამისამართებები და rewrite:** ხელით წესები, გვერდებთან კავშირები და საკუთარი წესები. იმპორტის შემდეგ rewrite ხელახლა გამოიყენეთ.
- **მედია:** რეგისტრირებული ფაილები, ვარიანტები და აღწერები; სხვა WHMCS attachments არ გადადის.

იმპორტი არსებულ შესაბამის ჩანაწერს განაახლებს, ახალს დაამატებს, დანარჩენს უცვლელს ტოვებს. არქივში არმყოფი არჩეული განყოფილება გამოტოვება. ახალ საიტზე მენიუს ან ავტომატური გადამისამართების გადატანისას შესაბამისი გვერდებიც აირჩიეთ. საწყისი საიტის SystemURL მიზნის მისამართით იცვლება, გარე URL ხელუხლებელია. გვერდებთან ერთად მედია აირჩიეთ სურათების გადასატანად.

ZIP-ის ზღვარი 128 MiB-ია, JSON-ის 32 MiB. გაითვალისწინეთ PHP upload_max_filesize და post_max_size; ZIP extension აუცილებელია. თუ შექმნილი CSS/JS აკლია ან ვერ იკითხება, ექსპორტი გამოტოვებს და გაფრთხილებას აჩვენებს. რევიზიები, შეგროვებული Smarty ცვლადები, WHMCS ანგარიშები და საიდუმლოებები, თემის ფაილები არ შედის. იმპორტი არსებულ ცხრილებს იყენებს და სქემას არ ქმნის.

ჩანაწერების შეცვლამდე ინტერფეისი დადასტურებას ითხოვს. მონაცემთა ბაზის ცვლილებები ტრანზაქციაშია, შეცდომისას ჩანაცვლებული ფაილები აღდგება. ფაილის ბლოკირება ერთდროულ იმპორტს უშლის ხელს. წარმატების შემდეგ sitemap ხელახლა შექმენით და საჯარო URL-ები შეამოწმეთ.
